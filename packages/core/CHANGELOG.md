# @callis/core

## 0.3.0

### Minor Changes

- 0fea378: Add the conversion functions: `iif()`, and `toBoolean()`, `toInteger()`, `toDecimal()`, `toDate()`, `toDateTime()`, `toTime()`, `toString()` and `toQuantity([unit])` with their `convertsTo…()` counterparts. `iif()` evaluates only the branch it selects, with the input as `$this`. A conversion takes one item: empty input gives empty, more than one item raises `eval/singleton-expected`, and a value that does not convert gives empty from `toX()` and `false` from `convertsToX()`. `toString()` keeps the precision of a Decimal and writes dates and times without `@`; `toQuantity(unit)` converts with the configured unit system.
- 0c82a86: Add `empty()`, `all(criteria)`, `allTrue()`, `anyTrue()`, `allFalse()`, `anyFalse()`, `subsetOf(other)`, `supersetOf(other)`, `distinct()` and `isDistinct()`, completing the existence functions with `exists()` and `count()`. `all()` stops at the first item whose criterion does not match, as `exists()` stops at a match. `allTrue()` and the other three take only Booleans; any other item raises `eval/type-mismatch`. `subsetOf()` and `supersetOf()` use `=`, and an item whose equality is undetermined is not a member. `distinct()` keeps the last of equal items, in input order, and returns the input items themselves. Items repeat only when `=` is true, as FHIRPath 3.0.0 says: values that cannot be compared, such as `@2020` and `@2020-01-01`, are distinct, so `isDistinct()` is never empty. An element that holds only extensions, such as one with only a data-absent-reason, is never equal to another item, so `distinct()` keeps it.
- e1b034d: Add the FHIR functions and variables. `extension(url)` filters extensions by URL; `hasValue()` is true for a single item with a primitive value and false otherwise, and `getValue()` gives that value; `resolve()` finds contained resources (`#id`) and the entries of a Bundle around a reference, by `fullUrl`, with a relative `Type/id` taken against the base of the entry it is in, and ignores anything else. `%resource` and `%rootResource` are the input by default, and the new evaluation options `resource` and `rootResource` set them; `%sct`, `%loinc`, `` %`vs-[name]` `` and `` %`ext-[name]` `` give their URLs. A `variables` entry of the same name still hides any of them, as before. `memberOf()`, `subsumes()`, `subsumedBy()`, `conformsTo()` and `htmlChecks()` now compile and return empty until host hooks arrive.
  
  With a model (internal so far), `~` follows FHIR's equivalence rules: `id` elements are ignored, a `Coding` compares on `system` and `code`, and two `CodeableConcept`s are equivalent when they share an equivalent coding. A FHIR Quantity without a UCUM code now compares with, and orders against, another FHIR Quantity with the same unit, also when the other one has a UCUM code: the same `code` when both have one, and otherwise the same `unit` text.
- 0cbee45: Add `first()` and `single()` to synchronous model-less evaluation. Both preserve selected input items; empty input returns empty, and `single()` raises `eval/singleton-expected` for multiple items.
- 582aff4: Add host hooks and asynchronous evaluation to the engine (on the internal API so far; the public API gets them with the expanded API, T0038, and is unchanged). The `hooks` evaluation option takes a `resolve` hook, which `resolve()` asks for references that are not in the data, a `terminology` provider behind `memberOf()`, `subsumes()` and `subsumedBy()`, a `conformsTo` hook, an `htmlChecks` hook, which gets strings as well as `xhtml` and is told which it received, a `regex` hook for a safe regular-expression engine behind `matches()` and `replaceMatches()`, and the `trace` hook. Without a hook the function gives empty; `undefined` from a hook gives empty, and an error it throws ends the evaluation. `evaluateAsync()` accepts promises and other thenables from every hook and from functions added with `registry.extend()`, and `evaluate()` raises `eval/async-in-sync` for one. A resource a `resolve` hook returns is typed by the model like the input. The `signal` option, any `AbortSignal`, stops an evaluation with `eval/aborted`, and the `concurrency` option bounds how many hook calls `resolve()` starts at once for one collection, with the results in input order.
- 6a7d079: Add the math functions `abs()`, `ceiling()`, `exp()`, `floor()`, `ln()`, `log(base)`, `power(exponent)`, `round([precision])`, `sqrt()` and `truncate()`. An empty input gives an empty result, more than one item raises `eval/singleton-expected`, and a value that is not a number raises `eval/type-mismatch`. Results that cannot be represented are empty: `(-1).sqrt()`, `(-1).power(0.5)` and an Integer result outside the 32-bit range. `abs()` also takes a Quantity and keeps its unit. `log()` of zero or a negative number, or to such a base, raises `eval/invalid-argument`, as does a negative `round()` precision. `power()` and `round()` always return a Decimal, as FHIRPath 3.0.0 specifies.
- 3186680: `ceiling()`, `floor()`, `round([precision])` and `truncate()` also take a Quantity, as FHIRPath 3.0.0 specifies, and return a Quantity with the same unit: `(5.5 'mg').ceiling()` is `6 'mg'` and `(5.55 'mg').round(1)` is `5.6 'mg'`. Before, they raised `eval/type-mismatch` for a Quantity. The value of the result stays a Decimal, so a whole number outside the Integer range is kept: `(3000000000.5 'mg').floor()` is `3000000000 'mg'`.
- 643512a: Add lossless JSON input: `parseJson(text)` parses JSON while keeping every number as written, as a `JsonNumber`, so `1.50` keeps its precision through evaluation (`decimalOutput: 'string'` gives `'1.50'`). Invalid text raises `eval/invalid-json`. Evaluation also understands `JsonNumber` values in input from other sources.
  
  The engine now evaluates with a `ModelProvider`: typed navigation of choice elements and FHIR primitives with their `_name` extensions, FHIR primitive values as System values (`date` as `Date`, `Quantity` with a UCUM code as `Quantity`), the root identifier as a type with inheritance, and `is`/`as` with model types. This is used by the conformance runner with the generated R4 and R5 models and tested against the R4, R5 and R6 providers; the public `model` and `lenient` options follow with the expanded public API (T0038). Model-less evaluation is unchanged.
- 2b5fd1a: Add `select(projection)`, `repeat(projection)` and `ofType(type)`. `select()` evaluates the projection for each item, with `$this` and `$index`, and flattens the results. `repeat()` applies the projection to the input and then to every new item, until no new item comes: an item is new unless it equals (`=`) one already found or is the same element of the input, so an element that holds only extensions is found once, and the result lists the new items breadth first. One `repeat()` call produces at most 5,000 items; a projection that keeps making new values, such as `'x'.repeat($this & 'x')`, raises `eval/limit-exceeded`. `ofType()` keeps the items of a type, with the same type resolution as `is` and `as`: without a model, a resource name keeps the objects whose own `resourceType` is that name, and a type that does not resolve, such as `FHIR.Patient` without a model, raises `eval/unknown-type`, also on empty input.
- b4e3717: Add static analysis. `analyze(expression, options?)` returns the diagnostics of an expression without compiling it: the errors `compile()` throws, with a span and a stable `semantic/…` code, plus warnings, and a syntax error as a diagnostic. `compile()` and `evaluate()` now run the same analysis first and throw `FhirPathSemanticError` with every diagnostic attached when it finds an error. New at compile time: an input or argument of a type a function never accepts (`'a'.abs()`, `skip('1')`, `toString()` on a complex value) is `semantic/type-mismatch` instead of an evaluation error; `$total` outside `aggregate()` is `semantic/undefined-variable`. New warnings: an operator whose operands it never accepts (`1 + 'a'`, which still raises `eval/type-mismatch` when evaluated), a type that does not resolve in `is`, `as` or `ofType()` (`semantic/unknown-type`, still `eval/unknown-type` when evaluated), and `semantic/fraction-ignored` when date/time arithmetic ignores part of a quantity written in the expression (`@2020-01-01 + 1.5 days` adds one day, as FHIRPath 3.0.0 says), which never changes the result. A `Diagnostic` may carry a `hint`.
  
  The `strict` compile option (N1 §11) makes the analyzer reject, as errors, a value that may repeat where an operator or function takes a single item (`(1 | 2) < 3`), equality between a single item and a collection, a value that is not a Boolean where one is expected (`iif('x', 1, 2)`), the operator warnings above, and `first()`, `last()`, `tail()`, `skip()`, `take()` or the indexer on `children()` or `descendants()`, whose order is undefined (`semantic/unordered-collection`). Without a model, analysis knows the types of literals, operators and functions, not of the input's elements; the model-aware checks (an unknown element, a choice element written with its type suffix, a leading type name that does not match the input) run inside the engine and reach the public API with the `model` option later.
- 5468cc1: Add the string functions `indexOf()`, `substring()`, `startsWith()`, `endsWith()`, `contains()`, `upper()`, `lower()`, `replace()`, `matches()`, `replaceMatches()`, `length()` and `toChars()`. Characters are Unicode scalar values, as in FHIRPath 3.0.0: a surrogate pair is one character. `matches()` and `replaceMatches()` use JavaScript regular expressions with the `u` flag in single-line mode, and a pattern that is not valid raises `eval/invalid-argument`. A `replaceMatches()` substitution refers to groups as `${name}` or `${1}` (the specification's form) or in JavaScript's forms (`$1`, `$<name>`, `$&`, `$$`). Regular expression flags and `matchesFull()` come later.
- 27ea77f: Add `last()`, `tail()`, `skip(num)`, `take(num)`, `intersect(other)`, `exclude(other)`, `union(other)` and `combine(other)`, completing the subsetting and combining functions with `first()` and `single()`. They return the input items themselves, in a fixed order: the input first, then the new items of `other`. `intersect()` and `union()` list equal items once, `exclude()` keeps duplicates, and `combine()` keeps every item. `union()` is the `|` operator. An item whose equality is undetermined, such as a date of another precision, is not equal. An empty `num` gives empty from `skip()` and `take()`; a `num` that is not a single Integer raises `eval/singleton-expected` or `eval/type-mismatch`.
- ef00a4b: Add `children()`, `descendants()`, `trace(name[, projection])`, `now()`, `today()` and `timeOfDay()`. `children()` lists the properties of each input object in document order, without `resourceType` and `_name` keys; `descendants()` lists everything below the input, depth first in document order. `now()`, `today()` and `timeOfDay()` read the clock once per evaluation and are in UTC unless `timezoneOffset` says otherwise. `trace()` returns its input unchanged; the hooks that receive its output come with the expanded public API.

### Patch Changes

- c7addb8: Count chains towards the nesting limit while parsing. Each step of a chain such as `a.b.c…`, `x.f().g()…`, `a[0][0]…` or `x and y and …` nests the chain before it one level deeper. Expressions deeper than 1,000 levels still raise `syntax/nesting-limit`, now with the span of the step that passes the limit instead of the chain's first node. Parentheses count as a level, as they already did for nested sub-expressions, now also when a chain continues after them: `(a.a….a).b` with 998 steps inside the parentheses is 1,000 levels deep without them and compiled before, and is now rejected.
- f408d5e: The package's `homepage` link on npm now opens its page on the documentation site, for example <https://callis.losol.no/packages/core/>, instead of its directory on GitHub.

## 0.2.0

### Minor Changes

- ac436db: Add `exists([criteria])` and `count()` to the synchronous model-less evaluator. Existence criteria reuse the established filtering predicate rules and stop at the first match. Empty collections return false for existence and zero for count; no public API options or async surface are added.
- 391ed2a: Add `where(criteria)` to the synchronous model-less evaluator. Filtering preserves order and input identity, supports nested item/index criteria, and follows the existing singleton Boolean and error rules without adding public API options.

## 0.1.0

### Minor Changes

- 049b205: Implement equality, equivalence, ordering, arithmetic, union and membership operators. Arithmetic preserves Decimal precision, enforces Integer bounds, supports Quantity unit conversion and calendar date/time quantities, and returns empty for numeric overflow or division by zero. Remove the temporary `eval/not-implemented` operator error code.
- 344d7e8: Export `Decimal`, `MAX_DECIMAL_DIGITS`, the `UnitSystem` contract types (`ParsedUnit`, `UnitConversionOptions`, `UnitProduct`, `UnitSystem`) and `minimalUnitSystem`, so that unit packages such as `@callis/ucum` can implement and extend the unit system.
- 95cf7fd: Add the internal equality, equivalence and ordering kernels behind `=`, `!=`, `~`, `!~`, `<`, `<=`, `>` and `>=`, with implicit Integer → Decimal, number → Quantity and Date → DateTime conversions, recursive comparison of complex JSON values, a hook for model-specific equivalence, and the model-less date convenience that reads input strings as dates when they are compared with a date/time. The operators that use them follow with the evaluator.
- e2c7274: Add internal Quantity values, minimal calendar and UCUM time-unit conversion,
  quantity comparison and arithmetic kernels, and FHIR Quantity mapping.
- 44b1ac6: Add the internal FHIRPath parser and readonly syntax tree, with exact literal text, source spans, qualified type names and bounded nesting. The public parse entry point will follow with the public API.
- da7c6f7: Add synchronous model-less `compile` and `evaluate` exports, plain result options and public error types. Use `decimalOutput: 'string'` to preserve exact evaluator Decimal and Quantity magnitudes. Existing model and unit-provider exports remain available. Broader function groups, model-aware evaluation and async APIs are deferred.
- cc25fd7: Export the `ModelProvider`, `ModelTypeInfo`, `ModelTypeKind`, `ElementInfo` and `SystemTypeName` types. A data model, such as the generated FHIR R4 and R5 models, implements `ModelProvider` to give the engine type-directed navigation and model-aware `is`, `as` and `ofType()`.

### Patch Changes

- 0bf76ff: Include the full MIT implementation license in the core and FHIR provider tarballs, preserving FHIR source notices and UCUM licensing. Include generated changelogs in all four package archives. Clarify the first 0.1 public subset and current UCUM integration in package documentation.
- 4730457: Add a README for npm and the `homepage` and `bugs` links to the package metadata.
