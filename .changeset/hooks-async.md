Add host hooks and asynchronous evaluation to the engine (on the internal API so far; the public API gets them with the expanded API, T0038, and is unchanged). The `hooks` evaluation option takes a `resolve` hook, which `resolve()` asks for references that are not in the data, a `terminology` provider behind `memberOf()`, `subsumes()` and `subsumedBy()`, a `conformsTo` hook, an `htmlChecks` hook, which gets strings as well as `xhtml` and is told which it received, a `regex` hook for a safe regular-expression engine behind `matches()` and `replaceMatches()`, and the `trace` hook. Without a hook the function gives empty; `undefined` from a hook gives empty, and an error it throws ends the evaluation. `evaluateAsync()` accepts promises and other thenables from every hook and from functions added with `registry.extend()`, and `evaluate()` raises `eval/async-in-sync` for one. A resource a `resolve` hook returns is typed by the model like the input. The `signal` option, any `AbortSignal`, stops an evaluation with `eval/aborted`, and the `concurrency` option bounds how many hook calls `resolve()` starts at once for one collection, with the results in input order.
